# NetRedirector v1.9.1

## IPv6 子網規則，以及「DNS 查不到來源時就偷偷走直連」的洩漏

這一版處理兩個都在**規則引擎**裡的問題：一個是 **IPv6 規則沒辦法寫子網**，
一個是**歸因失敗的 DNS 查詢會繞過你設定的代理**。兩者都不會報錯、不會中斷，
所以都不容易自己發現。

---

## 一、新增：IPv6 CIDR 子網規則（例 `2001:db8::/32`）

### 症狀

IPv6 的規則只能填**完整位址**。想擋或想導一個子網，例如「所有
`2001:4860::/32` 的流量走代理」，規則欄位填 `2001:4860::/32` 會**完全沒有效果，
也不會有任何提示** —— 它被當成一個字串去比對，永遠不會等於任何一個位址。

一個 /64 有 2⁶⁴ 個位址，所以「列出整個子網」不是選項：這個缺口等於
**IPv6 的規則功能實際上只有一半**。

### 修正

規則的 hosts 欄位現在支援 IPv6 的 CIDR 表示法：

```
2001:db8::/32      整個 /32 子網
::/0               全部 IPv6（等同 IPv6 的萬用字元）
2001:db8::/128     單一位址（與直接寫位址等價）
```

格式錯誤（前綴不是數字、超過 128、位址部分不合法）一律**視為不匹配**，
不會退化成字串比對 —— 否則打錯字會變成一條**永遠不匹配卻毫無提示**的規則。

設定介面的 hosts 提示文字也一併加上範例。

### 順帶修掉的一個無聲缺陷

「這個欄位裡有沒有域名」的判斷過去用的是 `is_ip_like_pattern()`，而它問的其實是
**「是不是點分 IPv4」**。於是任何含 `:` 或 `/` 的字串（IPv6 位址、以及新的 CIDR）
都被當成**域名**，每次新增或編輯這類規則就會多觸發**一次全機 DNS 解析快取清除**
外加兩次註定失敗的解析。既有的 IPv6 精確位址規則本來就會踩到，CIDR 只是讓它變常見。
現在改用專門的判斷（含 `:` 或 `/` 就是位址，不可能是主機名）。

> ⚠️ 已知限制：**IPv4 的 CIDR（例如 `10.0.0.0/8`）仍然是陷阱** —— IPv4 分支還沒有
> 同樣的處理，它會被當成域名解析、必然失敗、規則靜默永不匹配。要動 IPv4 CIDR 時
> 會連這條一起處理。

## 二、修正：DNS 查不到來源行程時，不再偷偷走直連

### 症狀

在「代理 + 一條萬用（`*`）規則」這種最常見的設定下，**大部分 DNS 查詢走代理，
但有一部分的查詢會走直連** —— 而且是明文送出。畫面上、日誌裡都不會有任何異常。

### 根因：同一個設定，兩種結果

引擎對每一條流量都要先問「這是哪個行程發的」。問不到的時候（`pid == 0`），
過去的行為是**無條件走「未知行程」的處置**（預設是直連）。

但 DNS 的處置其實**不該取決於「問不問得到行程」**：引擎另外有一個設定
「DNS 走代理」（`dns_via_proxy`，預設開）。於是同一台機器上會同時存在：

- 歸因**成功**的 DNS → 進規則 → 有萬用規則 → **走代理**；
- 歸因**失敗**的 DNS → 在進規則之前就被攔下 → **走直連**。

兩者用的是同一個設定，結果卻相反，而「漏掉的那一半」在日誌上跟正常流量長得一樣。

歸因失敗對 UDP 而言是常態（UDP 沒有 `TIME_WAIT`、沒有握手，socket 常常在引擎查表
之前就關掉了 —— Windows 的 DNS Client 是慣犯），所以這不是罕見路徑。

### 修正

`pid == 0` 且目的埠是 53 時，改成**與「查得到 pid 但查不到名稱」同一條路**：
帶著**空的行程名**繼續進規則比對。

- 萬用（`*`）、PID、域名規則照樣能匹配；
- 指名行程的規則自然不匹配（空名字不可能等於某個行程名）；
- 若沒有規則匹配，規則引擎本來就會回直連 —— 最壞情況與過去完全相同。

同時**維持對稱**：`dns_via_proxy` 關閉時，不論歸因成功或失敗，DNS 一律直連
（這個偏好優先於任何規則）。這條對稱是刻意保證的，否則就會出現
「一半 DNS 明文外洩」這種看不出來的洩漏。

另外把 `pid == 0` 時的「防迴圈」判斷（跳過自己行程）移進正確的分支 ——
`g_current_process_id` 在尚未初始化時是 0，原本會把 `pid == 0` 誤判成「自己」。

## 實機端到端驗證（新舊 DLL 對照）

C 測試只證明「比對與決策邏輯」，證明不了「實機真的改道」。這次兩項都做了
新舊 DLL 的配對量測（儀器是自製 SOCKS5 代理，記錄引擎實際交出去的東西）：

| 項目 | 舊版 | 新版 |
| :--- | :--- | :--- |
| IPv6 CIDR 規則 `2001:4860::/32` | `Direct (TCP)`，代理零記錄 | `Proxy (TCP)`，代理收到 `ATYP_IPV6` |
| 不涵蓋的 CIDR `2001:db9::/32` | `Direct (TCP)` | `Direct (TCP)`（對照組） |
| 歸因失敗的 DNS（`dns_via_proxy` 開） | **未被代理收到**（洩漏） | **被代理收到** |
| 歸因失敗的 DNS（`dns_via_proxy` 關） | 未被代理收到 | 未被代理收到（偏好優先） |

> 歸因失敗的 UDP 流量無法「隨手製造」—— 引擎有一層 socket 事件快取會先回答。
> 這次是用**壓力測試**逼出來的：灌爆引擎的 socket 事件佇列（它自己就設計成
> 「寧可丟事件也不要長大」），讓快取答不出來，再送 DNS 查詢。方法與腳本
> 在 `.workbuddy-ai/ab/`（`run_191_ab.py`、`run_flood_ab.py`）。

## 升級方式

使用內建自動更新即可。若更新流程本身有問題，直接下載本頁 zip 手動覆蓋
（`NetRedirector.dll` 必須與執行檔同目錄）。

> 提醒：設定檔 `config.json` 放在程式目錄。**手動換版本時請不要把整個資料夾
> 直接刪掉重解壓**，否則設定會跟著消失；內建自動更新會自動保留它。
